- action 路由采用 if/else 分支 + 末尾 switch 兜底的模式，每个 action 先校验参数再调 createWriterDB 执行业务逻辑，最后统一经 this.formatResult 包装返回。
- 对可能写库的破坏性操作（generateChapterOutlines、tuneWordCount 等）默认 dryRun=true 或 force=false，要求调用方显式传 true 才真正落库。
- LLM 可调用的 action 集中声明在 LLM_BOUND_ACTIONS Set 中，执行前统一走 _ensureLlmReachable 预检，失败时直接返回提示而不触碰数据库。
- dbPath 解析遵循「相对名落到 workspace/agents/{agent}/data/、绝对路径/~ 原样使用」的规则，并在 saveNovelPlan 新建库时对 info.name 做模糊匹配防分裂。
- 对外暴露的 schema 分为 MENU_ACTIONS（带 group/label/needsNovel/argsHint 的前端菜单项）与 AI_TOOLS（含 name/description/parameters 的 function schema），两者保持 action 名称一致但字段结构不同。
